# 南陵祭2027 開発ワークフロー (Japanese Workflow)

このスキルは、南陵祭2027プロジェクトにおいて、全ての成果物とコミュニケーションを日本語で行い、厳格なバージョニングとCHANGELOG管理、およびコミット運用を徹底するための手順です。

## ルール (Rules)

> [!CAUTION]
> ### 🚨 【最優先・絶対遵守】バージョニングの独断更新は「即不合格」 🚨
> 
> **AI（Antigravity等）は、ユーザーの明示的な「承認」なしにマイナーバージョン (0.X.0) やメジャーバージョン (X.0.0) を上げてはなりません。**
> 
> 1. **試行錯誤のログ = パッチ (Trial and Error = Patch)**:
>    開発中の変更（バグ修正、機能追加、調整等）は、統合されて実用できる状態になるまで **すべてパッチ番号 (0.0.Z) としてインクリメント** してください。
> 2. **マイナーバージョンの厳格管理 (Strict Minor Versioning)**:
>    マイナーバージョンを繰り上げるのは、ユーザーとAIの試行錯誤を経て、ユーザーが「完了・一区切り」を宣言・承認した時のみです。
> 3. **メジャーバージョンの基準 (Major Versioning)**:
>    メジャーバージョン (X.0.0) は、ユーザーが全ファイルを精査し「南陵祭本番で稼働できる」と判断した時のみです。
> 4. **CHANGELOGへの詳細集約 (Changelog Centralization)**:
>    全ての技術的知見・理由・原因は `CHANGELOG.md` に集約し、SSOT（唯一の真実）を維持してください。
> 5. **全言語日本語**: 成果物およびコミュニケーションはすべて日本語で行うこと。
> 6. **知識の永続化**: 設計決定は `DECISIONS.md` や適切なドキュメントへ同期すること。

## Git運用ルール（コミットメッセージ規定）

> [!IMPORTANT]
> ### 🚨 コミットメッセージは「バージョン番号のみ」とする 🚨
> 
> 1. **ユーザーからの指示必須**:
>    ユーザーから明示的に「コミットして」「プッシュして」等と指示された場合にのみGit操作を実行すること。勝手なコミットは禁止。
> 2. **コミットメッセージの書式**:
>    コミットメッセージは必ず `CHANGELOG.md` で採番した **現在のパッチバージョン番号のみ**（例: `0.1.1`）とすること。
>    - **【厳守】** プレースホルダーの括弧（`[` や `]`）も含めず、純粋な数字とドットのみの文字列（例: `"0.1.1"`）にすること。
>    - `feat: ...` や `fix: ...` などのプレフィックスや説明文は絶対に含めないこと。
> 3. **実行例**:
>    ```bash
>    git add .
>    git commit -m "0.1.1"
>    ```

## CHANGELOG更新手順

タスクの最後に必ず `CHANGELOG.md` を更新し、パッチ番号（v0.x.**X**）をインクリメントしてください。

> [!IMPORTANT]
> **更新前の絶対義務**:
> `CHANGELOG.md` を更新する前に、**必ずファイルの冒頭80行を読み込み**、以下の3点を確認すること。
> 1. **現在の最新バージョン**: 直近のパッチ番号を確認し、重複を避けてインクリメントすること。
> 2. **挿入位置**: 必ず「最新が一番上」になるよう、既存の最新エントリの直上に挿入すること。
> 3. **日付の整合性**: 日本標準時 (JST) に基づき、正しい日付を記載すること。

## [0.x.X] タスク名・概要 - YYYY-MM-DD

- ...

- ...
