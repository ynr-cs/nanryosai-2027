## 2. 2026年 モバイルオーダー導入見送りの真相（組織・運用・順序の記録）

2026年9月10日（本番前日）、完成していたモバイルオーダー／店頭セルフオーダー（SOK）／POS関連コード（21ファイル・9,642行）を本番ブランチから完全パージし、Webサイト単独運用へ切り替えた。原因は実装不足ではなく、以下の**承認順序と現場運用の構造的ボトルネック**にあった。

1. **8月6日 教員向けプレゼン（90分）でのスコープ誤認と共倒れリスク**
   - 資料に「21団体すべて」「並ばない南陵祭」「Webとモバイルオーダーは二つで、一つ」と記載した結果、教員陣に「全21団体へ一斉強制する無謀な計画」と受け止められた。
   - **近藤先生（3-1副担任・元民間企業）の本質的指摘**:
     - **食品衛生**: 調理や盛り付けの手とiPad/決済端末を触る手の交差汚染リスク（学校規定でも「調理者は販売に携わらない」「作り置き不可」「教室コンセントでの電気調理器使用不可」）。
     - **ヒューマンエラー**: 機械の故障以上に、番号の渡し間違い、商品の落下・作り直し、注文の一部未反映（「ズレ系エラー」）、スマホ忘れへの現場対応が最大の穴になる。
     - **一般来場者との公平性**: 生徒向けモバイルオーダーと一般客の店頭注文で待ち時間や見た目の不公平が生じないか。
     - **属人性（バス係数1）**: 開発者本人（山本洋昌）がシフト等で不在の瞬間に、誰が異常を検知し紙運用へ切り替える判断を下すのか。
2. **V4「個人情報ゼロ（Zero-PII）認証」による情報管理課題の技術突破（8月下旬）**
   - 藤本先生からの「県の教育用アカウント（`@gl.pen-kanagawa.ed.jp`）を未承認外部サービス（Firebase）へ保存・通過させるのはNG」という指摘に対し、Cloud Functionsのメモリ上のみでメールアドレス先頭4桁（南陵高校プレフィックス `0014`）を検証して即座に破棄し、Firestoreには `HMAC-SHA256` ハッシュUIDのみを記録する方式を確立した。
3. **3年1組パイロット転換後の「承認順序の逆転」とタイムアップ（8月31日〜9月10日）**
   - 3年1組『アキコのひとくちカステラ』（100円・約400個・当日焼成）での1店舗実証実験へ絞り込み、担任の坂本先生から「**大関先生（顧問）→ 近藤先生（副担任）→ 校長先生** の順序を厳守すること」と指示を受けた。
   - トング・カップ外持ちによる「全工程素手非接触」や「お渡し時AirPAY決済（金銭処理の物理分離）」、クラス過半数の賛同までは到達したものの、近藤先生への事前説明より先に生徒間で詳細詰めが先行し、本番2日前（9月9日水曜）に近藤先生から段取りの遅さ・LINE配布マニュアルの非現実性・貸与iPad（3年経過）のバッテリー懸念・紙運用の並行準備不足を厳しく指導された。
   - 9月9日深夜に物理掲示用『緊急時1ボタン停止マニュアル』等を完成させたが、校長面談が未設定のまま迎えた9月10日朝、3-1クラス代表および担任の判断により「本番前日に慣れない工程を入れてミスが出るリスクを避け、紙ベースで出店する」と決定。直ちに導入を取り下げ、関係各所へ感謝を伝えて翌日の現場見学へ切り替えたことで、人間関係と来年度への信頼を完全に守り抜いた。

## 3. 見送りによって紙一重で回避された「幻の本番炎上リスク」

コードおよびGA4実測データの事後検証により、仮に9月10日に強行導入していた場合、以下の複合障害が発生していたことが判明している。

1. **iOS 76.3% 環境でのWeb Push通知不能**: 来場者の **76.3%（300/394人）がiOS** だったにもかかわらず、実装上 `!isIOS` で通知登録を無効化しており（iOS Safariはホーム画面PWA追加なしではWeb Push不可）、かつService Workerに `notificationclick` がなく遷移先も `/status.html`（404）を指していた。
2. **`banned.html` 自動永久BAN・過激演出トラップ**: 呼出後に一定時間受取がない注文をCloud Schedulerが自動で「商品破棄」とし、利用者端末を強制ロックして過激な警告文言の `banned.html`（948行）へ追放するロジックが組まれていた。通知が届かないiOS生徒が次々と自動BANされる大惨事になるところだった。
3. **直前監査（9月9日）で検出されたP0脆弱性**: ローカル管理サーバー `admin-server.js` の `0.0.0.0` 無認証バインド＋コードインジェクション（校内Wi-Fiから `data.js` 汚染可能）、`app-shell.js` 緊急アラートの `innerHTML` Stored XSS、`createOrder` のトランザクション外重複チェック（TOCTOU）による受付番号枯渇DoSが存在していた。

## 4. GA4 × Cloud Monitoring 実測データが示す「4つの構造的真実」

### 4.1 リーチ（広報・流通）の敗因分析
- **見かけ394人 vs 実質会場内 約310〜330人**: Instagram経由146人のうち約4割（約58人）は会場にいない外部フォロワー（「幽霊ユーザー」）、さらにMetaのリンクプレビュークローラ6件（Prineville, Luleå, Boardman）や内部検証端末が含まれていた。全校約700人＋外部来場者約1,000人（計約1,700人）に対する実質到達率は **約18〜19%** にとどまった。
- **「画面の中のQRコード」入れ子トラップ**: 受付で配布された紙のQRコードを読むとスマホ画面で**パンフレットPDF**が開き、その最終ページにWebサイトのQRコードが画像として配置されていた。自分のスマホ画面内のQRは自分のカメラで読み取れず、タップ可能なハイパーリンクもなかったため、**外部来場者1,000人への最大導線がクリック1回（実質ゼロ）で完全沈黙**した。
- **「一部活動の自主制作」扱いの壁と配信遅延**: 公式インフラではなくCS部の非公式制作物だったため、受付案内ブースでのQR掲示が「特定部活の優遇」として当日朝に不許可となった。また校内ポスター4枚は2日目朝9:00掲示（全開催時間の34.6%のみ存在）、全校Google Classroom配信も2日目昼前（**全アクセスの66.5%が終了した後**）となった。
- **最大の単一施策は「校門横1時間の肉声勧誘」**: 9月12日 10:00〜11:00 に部長が校門横で紙QRを持って声をかけた1時間だけで **人間由来 約423 ops（全期間最高ピーク・前日午後6時間分の2倍・Instagramの単位時間効率の2.6倍）** を記録した。

### 4.2 UX・機能採用率の勝敗（分母＝394人）
- **勝った機能**:
  - **企画詳細の『この場所をマップで見る』文脈ボタン**: **51回（35人）** — 汎用マップリンク（2回）の **25.5倍**。
  - **トップページの注目企画カード**: **184回（89人）** — グローバルナビよりトップページのカード往復（平均2.30回表示）が主導線として機能。また「お知らせ」も専用ページではなくトップの抜粋プレビューで消費された。
  - **企画一覧（平均滞在80.5秒）＆ 会場スタッフ混雑更新（`venue.html`）**: 9人のスタッフが2日間で182回（約30分に1回）混雑状況を更新し、現場ツールとして定着した。
  - **マップの閲覧実態**: マップ閲覧83人に対しピン操作は49人（残り34人はピンを触らず一枚絵として閲覧）。初期描画状態での教室番号・企画名の視認性が重要。
- **負けた機能**:
  - **ログイン＆お気に入り**: `login.html` 到達39人の **平均滞在時間はわずか4.6秒**、お気に入り利用は外部来場者 **実質0人**（アプリ内WebViewのGoogle OAuth `403 disallowed_useragent` エラーと「数時間のイベントでアカウントは作らない」行動原理）。
  - **企画検索**: わずか **3人（5回 / 0.8%）**。
  - **CS部紹介ページ**: わずか **6人（1.5%）**。部活としての広報・新入部員獲得導線がフッター奥に埋没した。

### 4.3 インフラ・計測・セキュリティの教訓
- **74,399回のCloud Functions実行のうち96.7%（71,922回）が空回りcron**: 1分間隔のスケジュール関数4本を13日間止め忘れ、うち3本（53,944回・全体の72.5%）は中止されたモバイルオーダー用だった。人間由来の実行はわずか **479回（0.6%）**。この巨大な分母が、`loginVenueAdmin` の **21.4%失敗（44成功/12失敗）** など現場管理UIの高いエラー率を隠蔽した。
- **キャッシュ設計の成功**: 本番2日間の人間由来Firestore読み取りは約3,800 ops（**1 PVあたり約1.76回**）まで圧縮され、Blazeプラン従量課金下で無料枠上限の約15%・**実支払額 \$0** で完走した。
- **計測自爆とトークン露出**: `auth.js` がGA4の `page_view` 送信前に `history.replaceState` でクエリ文字列を消去したため、Classroom計測用の `?s=cr` がDirectに吸収されて検証不能になった。一方、`venue.html?token=...` の管理トークンがURLクエリ経由でGA4に記録された。

### 4.4 AI開発（バイブコーディング）で踏んだ4大アンチパターン
1. **Context Poisoning（文脈汚染）**: `antigravity/` に40以上の新旧マークダウンが乱立し、AIが古い仕様と新しい仕様を混同してバグを再生産した。
2. **`CHANGELOG.md`（1.01MB）の本番毎ページ `fetch` 事故**: 11,732行の履歴ファイルをクライアントJSが毎回取得していた。
3. **単一HTML 6,800行モノリス**: 型もコンポーネント境界もない巨大ファイル化により、局所修正が別機能を破壊した。
4. **AIハルシネーションデータの混入**: 未確定の企画名・メニューや、CLI省略表示（`...`）をAIが勝手に捏造・ハードコードした。

## 5. 南陵祭2027 設計・運用の「12の絶対鉄則」

1. **【制度化】春〜5月に文化祭実行委員会／生徒会と「公式共同インフラ」として提携**し、パンフ・受付ブース・放送・Classroomを制度として確保する。
2. **【早期承認】「顧問 → 担当教員・副担任 → 校長」の順序を厳守し、夏休み前（7月）までに決裁を完了**する（直前2週間での新規運用変更は厳禁）。
3. **【完全疎結合】公式Webポータルとモバイルオーダー／POSは、承認単位もコード境界も稼働キルスイッチも完全に分離**する。
4. **【QR×PDF対策】電子パンフ（PDF）内のQRコードには必ずタップ可能なハイパーリンク＋短縮URLを併記**し、全掲示物・配信リンクに個別の計測パラメータ（`?src=...`）を付与する。
5. **【現場主義】LINEでのPDFマニュアル配布を廃止し、ラミネート紙1枚の物理掲示＋前日試食会での実機リハーサル＋貸与端末の給電計画を必須化**する。食品は全工程トング／カップ外持ちで素手非接触を徹底する。
6. **【ログインレスUX】一般来場者・生徒の閲覧体験からログイン関門を完全撤廃**し、お気に入り等は `localStorage` で即完結させ、Instagram/LINE等のアプリ内WebViewで100%動作させる。
7. **【iOS 8割前提】Web Pushを主要連絡手段にしない**。トップ画面上部の常設ライブバナー＋店頭モニター＋リアルタイム注文ステータス画面を主軸とし、自動破棄・自動BAN等の懲罰仕様は一切排除する。
8. **【認証・管理UI】校内限定機能が必要な場合はV4のZero-PII方式を継承**し、現場スタッフ画面はパスワード手入力を廃止してワンタイムQR＋当日セッション維持とする。
9. **【Cron統制】1分間隔cronの常時稼働を禁止**し、イベント開催時間帯限定＋機能フラグ連動の自動停止機構を組み込む。
10. **【計測＆防御】GA4発火前の `replaceState` 禁止、URLクエリへのトークン露出禁止、CSPヘッダー・`innerHTML` 排除・Firestoreトランザクション内排他ロック（TOCTOU防止）を徹底**する。
11. **【TypeScript SSOT】単一巨大ファイルと仕様書の散乱を禁止**し、TypeScriptの厳格な型定義と `DECISIONS.md` を唯一の正（SSOT）とする。`CHANGELOG.md` はアプリ実行時に一切読み込まない。
12. **【バス係数 > 1】3年生（山本洋昌）個人のSNSや徹夜対応に依存しない広報・運用・コード構造を構築し、1・2年生へ確実に継承**する。
